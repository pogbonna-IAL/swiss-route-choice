# 7. Architecture

How the code is arranged, why the run order is not the file order, and what
keeps a multi-hour pipeline recoverable.

---

## 7.1 File map

```
R/
  00_setup.R          paths, shared constants, IO helpers, resume switch, provenance
  lc_helpers.R        latent class: code generation, starts, canonical ordering,
                        multi-start driver, delta-method valuations, fit caching
  model_helpers.R     hold-out split, scoring (closed-form and panel simulated),
                        exact binary logit
  01_data_audit.R     panel structure, missingness, dominance, non-traders
  02_mnl.R            baseline MNL + mlogit cross-check + hold-out
  03_mnl_covariates.R observed heterogeneity
  04_mixed_logit.R    continuous unobserved heterogeneity
  05_lc_2class.R      covariate class allocation, K = 2..4
  06_lc_multiclass.R  LC1-LC5, constant-only allocation
  07_lc_stability.R   stability verdicts
  08_small_sample_experiment.R  resampling experiment
  09_idefix_design.R  Bayesian D-efficient design
  11_breakdown.R      where latent class estimation stops working
  10_report.R         assembles the report from outputs/tables
  build_docs.R        bundles docs/ into one markdown file
  build_reference.R   freezes the headline results as a reproduction target
  run_all.R           the real run order
  orchestrate.R       run records, marker scanning, notifications
tests/
  run_tests.R         entry point
  testthat/           221 assertions across nine files
docs/                 this documentation
outputs/
  models/ figures/ tables/ logs/
  report.md           the analysis report (generated by 10)
  documentation.md    docs/ bundled into one file (generated by 10)
  session_info.txt    package versions for the last full run
```

Four shared files, each with one job:

- **`00_setup.R`** — everything every script needs: paths, `SEED`, `FULL_N`,
  `ROUTE_ATTRS`, `MODEL_COVARS`, `write_table()`, `cached_model()`.
- **`lc_helpers.R`** — everything latent-class-specific. Sourced by `05`, `06`
  and `08`.
- **`model_helpers.R`** — validation machinery. Sourced by `02`, `03` and `04`.
- **`orchestrate.R`** — what happens *around* each step: run records, log
  marker scanning, notifications. Sourced by `run_all.R`.

## 7.2 The dependency graph

**The file numbering is not the run order.**

```
                          01_data_audit
                                |
                          02_mnl  ────────────────────────┐
                          /  |  \                          \
                         /   |   \                          \
              03_mnlcov  04_mxl  06_lc_multiclass      08_small_sample
                                        |                    |
                                  05_lc_2class               |
                                        |                    |
                                        └──── 07_stability ──┘
                                                  |
                          09_idefix ─────────── 10_report
```

Two edges run *backwards* through the numbering:

| Script | Reads | Written by |
|---|---|---|
| `05_lc_2class.R` | `06_lc_comparison.csv` | `06` |
| `07_lc_stability.R` | `08_fits.csv`, `08_parameters.csv`, `06_lc_comparison.csv`, `06_lc_parameters.csv` | `08`, `06` |

Running the scripts in filename order **fails at `05`**. The real order is

```
01 → 02 → 03 → 04 → 06 → 05 → 08 → 07 → 09 → 10
```

### Why not renumber?

Renaming `06` to `05` and vice versa would rename every output file
(`05_lccov_*.csv`, `06_lc_*.csv`), orphan the 1,044 latent class fits already in
`08_fits.csv`, and invalidate every cross-reference in the report — to fix a
problem that one ordered list solves. `run_all.R` holds the order and checks
each script's declared inputs *before* running it:

```r
run_step <- function(step, script, needs, note) {
  missing <- needs[!file.exists(vapply(needs, find_input, character(1)))]
  if (length(missing)) {
    stop(sprintf("step %s (%s) needs %s, which does not exist yet.", ...))
  }
  ...
}
```

A partial pipeline fails with a message naming the missing table and the step
that produces it, rather than a `file not found` forty lines inside someone
else's script.

## 7.3 Process isolation

**Each script runs in its own R process.**

```r
status <- system2(rscript, args = shQuote(here::here("R", script)),
                  stdout = log_path, stderr = log_path)
```

This is not tidiness. Apollo keeps its model definition in the **global
environment** — `apollo_probabilities`, `apollo_randCoeff`, `apollo_lcPars` —
and reads it by name at estimation time. Consequences:

- A leftover `apollo_randCoeff` from `04` would silently turn `05`'s latent
  class model into a mixed logit.
- `apollo_control$mixing = TRUE` from `04` would change how `06` integrates.
- A stale `apollo_lcPars` from a $K = 3$ model would corrupt a $K = 1$ fit.

`lc_install()` defensively removes `apollo_lcPars` when $K = 1$, but that
guards one object inside one loop. Process isolation guards everything, and it
is the only approach that stays correct as scripts are added.

## 7.4 Caching and resume

The three long scripts each cache completed work and resume:

| Script | Granularity | Mechanism |
|---|---|---|
| `04` | one model | `cached_model()` → `Swiss_MXL_*_model.rds` |
| `05` | one $K$ | `lc_fit_cached()` → `_model.rds` + `_runs.rds` |
| `06` | one $K$ | `lc_fit_cached()` → `_model.rds` + `_runs.rds` |
| `09` | the design | `resume_enabled()` → `idefix_design_D.rds` |
| `08` | one $(n, \text{seed}, K)$ | append to CSV, `anti_join` on restart |

```r
lc_fit_cached <- function(key, fit_fn, resume = TRUE) {
  model_path <- file.path(PATH_MODELS, paste0(key, "_model.rds"))
  runs_path  <- file.path(PATH_MODELS, paste0(key, "_runs.rds"))

  if (resume && file.exists(model_path) && file.exists(runs_path)) {
    return(lc_fit_result(readRDS(model_path), readRDS(runs_path)))
  }
  fit <- fit_fn()
  if (isTRUE(fit$ok)) {
    saveRDS(fit$model,   model_path)
    saveRDS(fit$run_log, runs_path)
  }
  fit
}
```

Three design points:

1. **The model and its run log are cached together, and both are required.**
   A half-written cache cannot be mistaken for a complete one.
2. **Derived quantities are recomputed, not stored.** `n_at_best` and
   `hessian_ok` come from `lc_fit_result()` reading the cached objects, so they
   cannot drift from the model they describe.
3. **`REFIT=1` bypasses every cache**, project-wide, via `resume_enabled()` in
   `00_setup.R`.

`08`'s resume keys on the **triple** $(n, \text{seed}, K)$, not the cell.
Keying on the cell would mean that widening `K_SET` — adding LC4 to an
experiment that already ran MNL/LC2/LC3 — marks every existing cell incomplete
and re-estimates hundreds of models that are already correct and on disk.

This is not a theoretical nicety. During development the OS memory watchdog
killed `05` three times mid-sweep; with per-$K$ caching it completed across two
runs, banking $K=2$ and $K=3$ in the first and only estimating $K=4$ in the
second.

## 7.5 Shared constants

Previously `SEED`, `FULL_N`, the attribute list and the covariate list were
redeclared in up to five scripts each. That makes it possible for the script
that *writes* a table and the script that *reads* it to disagree — `07` sizes
its output against `FULL_N` while `08` resamples against its own copy.

All now live in `00_setup.R`:

```r
SEED   <- 20260903L
FULL_N <- 388L
ROUTE_ATTRS       <- c("tt", "tc", "hw", "ch")
ROUTE_ATTR_LABELS <- c(tt = "travel time (min)", ...)
MODEL_COVARS      <- c(log_income = "inc", car_availability = "car", ...)
```

`MODEL_COVARS` maps **data column → parameter suffix**, so `03` builds
`g_tt_inc` and `05` builds `g_inc_2` from one definition. `01_data_audit.R`
asserts `n_distinct(ID) == FULL_N`, so if the data ever changes underneath the
constant it surfaces in the audit rather than three scripts later in a
silently mis-scaled experiment.

## 7.6 Output conventions

Every deliverable goes through one helper, so the naming convention is
enforced in one place rather than open-coded in eight scripts:

```r
write_table(x, name, prefix)    # -> outputs/tables/<prefix>_<name>.csv
write_figure(p, name, prefix, width, height)  # -> outputs/figures/<prefix>_<name>.png
show_table(x, digits)           # console display, full precision preserved on disk
```

`show_table()` rounds for the console **without** touching the object written
to disk. Tables keep full precision; the terminal gets something readable.

### Why `saveRDS` rather than `apollo_saveOutput`

`apollo_saveOutput` renames any existing file to `_OLD1`, `_OLD2`, … on every
re-run. A few re-estimations leave the model directory full of stale copies
that no script reads and nothing cleans up — four such orphans existed before
this was changed. Every script now uses `saveRDS` plus an explicit
`writeLines(capture.output(apollo_modelOutput(m)))` for the human-readable
version.

## 7.7 Package loading

`00_setup.R` attaches only what **every** script needs: `here`, `tidyverse`,
`apollo`, `patchwork`. Script-specific dependencies are attached where used:

| Package | Used by | Why not global |
|---|---|---|
| `mlogit` | `02` | Only the cross-check needs it |
| `idefix` | `09` | Attaches `shiny` as a side effect |
| `knitr` | `10` | Only the report uses `kable()` |

Six packages were previously attached and used nowhere — `data.table`,
`broom`, `MASS`, plus `mlogit`, `idefix` and `knitr` whose stated purposes were
never implemented. `idefix` matters most: it pulls in `shiny`, which has no
business on the search path of a script that only estimates a model.

The `select <- dplyr::select` pin is retained as a guard. Nothing on the
default search path masks it today, but `09` attaches `idefix`, and a silent
mask is a confusing failure.

## 7.8 Testing

`tests/run_tests.R` runs 221 assertions across nine files. They cover the
**pure helpers only** and deliberately estimate nothing — a suite that takes an
hour is a suite nobody runs.

| File | Covers |
|---|---|
| `test-lc-canonical.R` | Ordering preserves class shares; covariate re-referencing preserves membership for random covariate vectors; atomic-vector inputs |
| `test-lc-verdict.R` | Convergence without a covariance matrix is not usable; each failure flag fires; separation is scale-free; the announcement is greppable |
| `test-lc-params.R` | Parameter-count arithmetic; contrast standard errors; reproducible starts |
| `test-lc-codegen.R` | Generated source contains the right parameters; $K=1$ guards |
| `test-model-helpers.R` | Split is on respondent; scoring identities; overflow and underflow; draws are all used |
| `test-setup-constants.R` | `FULL_N` matches the data; covariates exist as columns; naming conventions |
| `test-reproduction.R` | Twenty headline quantities match `tests/reference/expected_results.csv`; the 1,044-fit ledger is intact |
| `test-no-local-paths.R` | No committed model cache carries this machine's project path |
| `test-orchestrate.R` | Every log marker is still emitted by the file that should emit it; the scanner counts rather than lists |

Estimation itself is checked **inside the scripts** by the assertions listed in
[Validation §4.4](04-validation.md#44-assertions-in-the-pipeline), because
those require fitted models and belong where the fitting happens.

### A note on fixture design

Two tests exist because earlier versions of them passed against real bugs:

- The identical-draws test verified the log-sum-exp arithmetic and was blind to
  the fact that only draw 1 was reaching it — because with identical draws,
  draw 1 is the right answer.
- The list-based fixtures for `lc_par_value` never exercised the atomic-vector
  path that Apollo actually returns.

**A fixture that is degenerate in the same dimension as the bug cannot catch
the bug.** Both now use fixtures that vary in exactly the dimension that
matters.

## 7.9 Running it

```sh
Rscript R/run_all.R              # everything, in dependency order
Rscript R/run_all.R --list       # the plan, then exit
Rscript R/run_all.R --resume     # restart at the first step that did not finish
Rscript R/run_all.R --from 06    # 06 and everything after it
Rscript R/run_all.R 02 06 05     # just those, still in dependency order
REFIT=1 Rscript R/run_all.R      # ignore every cache, re-estimate everything
Rscript tests/run_tests.R        # helper suite
```

The expensive fits are **committed**, so these are the costs a clone actually
pays:

| Scenario | Time | What happens |
|---|---|---|
| Fresh clone | **~3-4 min** | Every model and the design load from cache |
| After deleting `outputs/models/` | ~100 min | 04 (20), 06 (45), 05 (30), 09 (5) re-estimate; 08 resumes from its committed CSVs |
| `REFIT=1` | ~6 hours | Everything from scratch, including all 1,044 fits in 08 |

Nominal per-step costs, for the middle row: 04 ~20 min (200 MLHS draws, two
models plus a training-half fit), 06 ~45 (5 models × 50 starts), 05 ~30
(3 models × 30 starts), 09 ~5, 08 ~240 for 1,044 fits from nothing, everything
else under a minute.

Pre-flight prints the estimate before the run starts, taken from what each
step actually took last time rather than from this table.

## 7.10 The orchestration layer

`run_all.R` decides what runs and in what order. `orchestrate.R` decides what
happens around each step.

It exists because the orchestrator used to report *process* success and call it
done. Step 05 printed two `UNUSABLE` banners -- `LCcov3` and `LCcov4` have
singular Hessians on the full panel, every standard error `NA` -- into its own
log, and the summary line said `ok`. The scripts already said the right things;
nothing read them back. That is the same "converged is not usable" confusion
the fit-level verdict fixed inside the scripts, recurring one level up.

**Marker scanning.** After each step, its log is scanned for literal strings
the scripts are known to print, and hits are surfaced as counts with a line
number:

```
[05] 05_lc_2class.R -- covariate class allocation, K = 2..4
     done in 0.16 min   !! 3 critical  ~ 1 warning
     -> unusable model fit (x2), log line 134
     -> model not estimable (x1), log line 336
```

Literal matching is fast and predictable and **fails silently**: reword a
`cat()` and the marker stops firing, the step reports `ok`, and the finding is
lost exactly as before. So `ORCH_MARKERS` records which file must emit each
pattern and `test-orchestrate.R` asserts it is still there. Writing that guard
immediately found two markers that had never matched anything.

**Severity policy.** Critical findings do **not** fail the run. An inestimable
model is a result, and a pipeline that refused to finish over one would be
unusable. The one thing that fails, with a non-zero exit code, is reproduction
drift -- the pipeline no longer producing the numbers this repository claims.

**Run records.** Each run writes `outputs/runs/<timestamp>/`: per-step logs
stamped with start, finish and exit code; a machine-readable `run.json`; and a
`summary.md`. The last ten are kept. `--resume` reads the latest record and
restarts at the first step that did not finish.

**Pre-flight.** Before anything runs: renv sync, which steps hit cache, and how
long it will take -- from measured times where a previous run recorded them. An
early version resolved cache artefacts only against `outputs/models/`, so 08
(which resumes from CSVs) looked uncached and drew a 240-minute estimate onto a
12-second step. An estimate that cries wolf gets ignored, and then it is not an
estimate.

**Notifications** are opt-in, so a clone behaves exactly as before:

```sh
NOTIFY_DESKTOP=1 Rscript R/run_all.R
NOTIFY_WEBHOOK=https://hooks.slack.com/... Rscript R/run_all.R
```

On failure the runner prints the *error* lines rather than the last 25 lines of
log, which were usually Apollo's startup banner. `save_session_info()` records
the package versions that produced the run.
